# DAM 库坝应急巡查工作流生成系统

## 1. 项目概述

### 1.1 定位

**库坝应急巡查智能感知系统中的工作流规划智能体**。系统根据**已确定的事件类型**和现场图片，自动规划最合理的视觉分析流程，并生成专业的事件分析报告。

**核心特点**：
- **事件类型已确定**：由传感器、规则引擎或变化检测模块预先判断，本系统不重新判断事件是否发生
- **自动工作流规划**：根据事件类型自动生成 DAG（有向无环图）工作流
- **智能模型选择**：基于事件类型和任务需求，自动选择最合适的模型组合
- **高效 IO 配对**：三层匹配策略（模板→规则→LLM 兜底）确保数据流正确传递

### 1.2 核心设计原则

| 原则 | 说明 |
|------|------|
| **专有模型优先** | 优先调用针对具体任务微调后的专有模型完成视觉识别 |
| **小模型优先** | 能够由轻量模型完成的任务，不调用多模态大模型 |
| **大模型负责理解与推理** | 仅在需要综合分析时调用大模型，不重复执行识别任务 |
| **避免重复分析** | 专有模型已完成的识别任务，大模型不再重复执行 |
| **工作流简洁高效** | 仅调用完成当前事件分析所必需的模型 |

### 1.3 系统特点

| 特点 | 说明 |
|------|------|
| **输入** | 结构化输入（事件类型 + 图片 + 传感器数据） |
| **节点类型** | START / ACTION / END（无 CONDITION 节点） |
| **DAG 生成** | 模板匹配 + LLM 兜底（8B 模型） |
| **模型挂载** | 事件→模型映射表 + 规则匹配 |
| **IO 配对** | 固定模板优先，LLM 兜底（0.8B 模型） |
| **校验** | 轻量校验（START/END 存在性、连通性） |
| **输出** | 仅事件分析报告（不暴露内部流程） |
| **LLM 调用次数** | 0-2 次 |

## 4. 系统架构

### 4.1 三阶段流水线

系统采用三阶段流水线架构，每个阶段职责明确：

```
输入 → [阶段1: DAG 生成] → [阶段2: 模型挂载] → [阶段3: IO 配对] → 输出
         ↓                    ↓                    ↓
      draft_dag           populated_dag          final_dag
```

| 阶段 | 模块 | LLM 调用 | 使用模型 | 说明 |
|------|------|----------|----------|------|
| 1 | `dag_generator` | 0-1 次 | 8B 模型 | 基于事件类型生成 DAG 骨架（节点 + 边） |
| 2 | `model_selector` | 0 次 | - | 为 ACTION 节点挂载模型，为 LLM 节点注入配置 |
| 3 | `io_configurator` | 0-1 次 | 0.8B 模型 | 模板匹配 IO 配对，不匹配时 LLM 兜底 |

**LLM 调用预算**：最多 2 次（dag_generator 1 次 8B + io_configurator 兜底 1 次 0.8B）

### 4.2 状态流转

```python
class DamState(TypedDict, total=False):
    # --- 输入 ---
    event_type: str                        # 已确定的事件类型
    images: List[str]                      # 现场图片路径列表（必需）
    sensor_data: Optional[dict]            # 传感器信息、设备信息（可选）
    user_prompt: str                       # 完整系统 prompt

    # --- 中间产物（内部使用，不对外暴露） ---
    draft_dag: Optional[Dict]              # dag_generator 输出
    populated_dag: Optional[Dict]          # model_selector 输出
    final_dag: Optional[Dict]              # io_configurator 输出

    # --- 输出 ---
    result_dag: Optional[List[Dict]]       # 最终可执行 DAG（内部使用）
    analysis_report: Optional[str]         # 最终事件分析报告（对外输出）

    # --- 错误 ---
    error_signal: Optional[ErrorSignal]    # 错误信号
    retry_count: int                       # 重试计数
```

### 4.3 节点类型体系

| 节点类型 | 说明 | 实现类型 | 是否必须 |
|----------|------|----------|----------|
| `START` | 入口节点，接收结构化输入 | 无 | 必须，有且仅一个 |
| `ACTION` | 执行节点，挂载专有模型或大模型 | MODEL / CODE | 至少一个 |
| `EVALUATION` | 评价节点，生成最终事件分析报告 | MODEL（固定 LLM） | 必须，有且仅一个，位于 END 之前 |
| `END` | 出口节点，输出最终报告 | 无 | 必须，有且仅一个 |

**拓扑约束**：
```
START → [专业识别_1 → 专业识别_2 → ... → 智能推理] → EVALUATION → END
```

- 无 CONDITION 节点：应急巡查场景下工作流为线性流程
- 专业识别在前，智能推理在后
- EVALUATION 强制存在且紧邻 END

### 4.4 模型类别

| 类别 | 模型类型 | 职责 | 示例 |
|------|----------|------|------|
| `specialized` | 专有微调模型（小模型） | 目标检测、语义分割、变化检测、缺陷分类 | YOLOv8 裂缝检测、U-Net 渗漏分割 |
| `local_llm` | 本地大模型（qwen4B） | 场景推理，生成初步报告 | 场景分析、风险评估 |
| `cloud_llm` | 云端大模型（qwen35B） | 综合分析，生成最终报告 | 综合分析、处置建议 |

## 5. 核心模块详解

### 5.1 输入解析（input_parser.py）

**功能**：从用户 prompt 中提取事件类型

**实现方式**：纯规则匹配，无 LLM 调用

**支持的事件类型**：
- 滑坡 (landslide)
- 裂缝 (crack)
- 渗漏 (seepage)
- 变形 (deformation)
- 沉降 (settlement)
- 管涌 (piping)
- 降雨 (rainfall)
- 水位 (water_level)

**关键词映射**：
```python
EVENT_KEYWORDS = {
    "滑坡": ["滑坡", "山体滑坡", "边坡失稳", "滑动", "landslide"],
    "裂缝": ["裂缝", "裂纹", "开裂", "龟裂", "crack"],
    "渗漏": ["渗漏", "渗水", "漏水", "渗流", "seepage"],
    "变形": ["变形", "位移", "形变", "偏移", "deformation"],
    "沉降": ["沉降", "下沉", "地面沉降", "settlement"],
    "管涌": ["管涌", "涌水", "涌砂", "piping"],
    "降雨": ["降雨", "暴雨", "大雨", "下雨", "rainfall"],
    "水位": ["水位", "水位升高", "水位异常", "water_level"],
}
```

### 5.2 DAG 生成器（dag_generator.py）

**功能**：阶段 1，生成 DAG 骨架

**策略选择**：

| 条件 | 策略 | LLM 调用 | 使用模型 |
|------|------|----------|----------|
| 事件类型命中预定义模板 | 模板实例化 | 0 次 | - |
| 事件类型未命中模板 | LLM 生成 | 1 次 | 8B 模型 |

**事件模板示例（滑坡）**：
```python
{
    "description": "滑坡事件应急巡查工作流",
    "visual_tasks": ["滑坡区域检测", "场景推理与初步报告", "综合分析与最终报告"],
    "nodes": [
        {"node_id": "start_0", "node_class": "START", "node_type": "输入接收"},
        {"node_id": "action_detect", "node_class": "ACTION", "node_type": "滑坡区域检测",
         "expected_implementation_type": "MODEL", "model_category": "specialized"},
        {"node_id": "action_reasoning", "node_class": "ACTION", "node_type": "场景推理与初步报告",
         "expected_implementation_type": "MODEL", "model_category": "local_llm"},
        {"node_id": "action_report", "node_class": "ACTION", "node_type": "综合分析与最终报告",
         "expected_implementation_type": "MODEL", "model_category": "cloud_llm"},
        {"node_id": "end_0", "node_class": "END", "node_type": "输出"},
    ],
    "edges": [
        {"source": "start_0", "target": "action_detect"},
        {"source": "action_detect", "target": "action_reasoning"},
        {"source": "action_reasoning", "target": "action_report"},
        {"source": "action_report", "target": "end_0"},
    ],
}
```

**轻量校验**：
1. START/END 存在性：必须有且仅有一个 START 和一个 END
2. 必需节点检查：必须有 local_llm 和 cloud_llm 节点
3. 连通性：从 START BFS 能到达所有节点

### 5.3 模型选择器（model_selector.py）

**功能**：阶段 2，为 DAG 中的节点挂载模型

**选择流程**：
1. 对于 local_llm 和 cloud_llm，优先使用配置的默认模型 ID
2. 从事件→模型映射表查询候选模型
3. 按优先级选择最佳模型
4. 从 model_registry + model_deploy_binding 获取完整信息（含推理地址）
5. 映射表无命中时，模糊匹配
6. 无数据库连接或未找到，返回占位信息

**模型信息结构**：
```python
{
    "model_id": 123,
    "model_name": "YOLOv8 裂缝检测",
    "model_type": "object_detection",
    "framework": "PyTorch",
    "inference_url": "http://192.168.31.52:8080/predict",
    "io_schema": {
        "inputs": [...],
        "outputs": [...]
    }
}
```

### 5.4 IO 配对器（io_configurator.py）

**功能**：阶段 3，为 DAG 中的边匹配数据流

**三层匹配策略**：

```
Layer 1: 模板匹配（0 LLM）
    ↓ 未命中
Layer 2: 规则匹配（0 LLM）
    ↓ 未命中
Layer 3: LLM 兜底（1 LLM，使用 0.8B 模型）
```

**规则匹配逻辑**：
1. 字段名精确匹配
2. 类型兼容匹配（基于类型兼容矩阵）

**类型兼容矩阵**：
```python
TYPE_COMPAT = {
    "image": {"image", "file", "str", "any"},
    "object": {"object", "dict", "any"},
    "array": {"array", "list", "any"},
    "string": {"string", "str", "any"},
    "float": {"float", "number", "int", "any"},
    "int": {"int", "integer", "float", "number", "any"},
}
```

### 5.5 模型库客户端（model_registry_client.py）

**功能**：调用模型库推理接口

**主要方法**：
- `get_model_name(model_id)`: 动态获取模型的 vLLM served-model-name
- `infer(model_id, request_data)`: 调用模型推理

**调用方式**：
```python
# 自动将 prompt 格式转换为 messages 格式
result = model_registry_client.infer(
    model_id=10,
    request_data={"prompt": "请分析这个滑坡事件"}
)
```

**返回格式**（vLLM 标准格式）：
```json
{
    "data": {
        "choices": [
            {
                "message": {
                    "content": "分析结果..."
                }
            }
        ]
    }
}
```

## 6. 数据库设计

### 6.1 DAM 专属表

#### 6.1.1 model_event_mapping — 事件→模型映射表

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT | 主键 |
| event_type | VARCHAR(64) | 事件类型（滑坡/裂缝/渗漏/变形/沉降/管涌/降雨/水位） |
| task_type | VARCHAR(128) | 任务类型（检测/分割/变化检测/场景推理/最终报告） |
| model_category | ENUM | 模型类别：specialized=专用小模型，local_llm=本地大模型，cloud_llm=云端大模型 |
| model_id | BIGINT | 模型 ID（关联 model_registry.id） |
| priority | INT | 优先级（数值越大越优先） |

#### 6.1.2 model_evaluation_template — 评价 prompt 模板表

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT | 主键 |
| template_name | VARCHAR(128) | 模板名称（唯一） |
| event_type | VARCHAR(64) | 适用事件类型（NULL 表示通用模板） |
| template_type | VARCHAR(32) | 模板类型：reasoning=场景推理，report=最终报告 |
| prompt_template | TEXT | prompt 模板（含占位符） |
| input_schema | JSON | 输入 schema 定义 |
| output_schema | JSON | 输出 schema 定义 |
| is_active | TINYINT(1) | 是否启用：0=禁用，1=启用 |

#### 6.1.3 model_io_template — IO 配对模板表

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT | 主键 |
| template_name | VARCHAR(128) | 模板名称 |
| event_type | VARCHAR(64) | 适用事件类型（NULL 表示通用） |
| source_model_category | VARCHAR(64) | 上游模型类别 |
| target_model_category | VARCHAR(64) | 下游模型类别 |
| field_mapping | JSON | 字段映射规则 |

### 6.2 依赖的模型库数据（只读）

| 数据 | 来源表 | 用途 |
|------|--------|------|
| 模型基本信息 | `model_registry` | 查询可用模型 |
| 模型部署信息 | `model_deploy_binding` | 获取推理地址 |
| 模型 IO Schema | `model_io_schema` | 获取输入输出定义 |

## 12. 常见问题

### 12.1 服务启动失败

**问题**：`ModuleNotFoundError: No module named 'src'`

**解决**：确保在项目根目录下运行，并激活虚拟环境

```bash
cd /home/jetson/box_system/dam-workflow
source venv/bin/activate
python main.py
```

### 12.2 数据库连接失败

**问题**：`pymysql.err.OperationalError: (2003, "Can't connect to MySQL server")`

**解决**：
1. 检查数据库服务是否启动
2. 检查 `.env` 中的数据库配置是否正确
3. 检查网络连接和防火墙设置

### 12.3 模型库调用失败

**问题**：`httpx.ConnectError: Connection refused`

**解决**：
1. 检查模型库服务是否启动
2. 检查 `.env` 中的 `MODEL_REGISTRY_API_BASE` 配置
3. 检查模型 ID 是否正确配置（`LLM_LOCAL_MODEL_ID` 等）

### 12.4 事件类型无法识别

**问题**：`ValueError: 无法从 prompt 中识别事件类型`

**解决**：
1. 检查 prompt 中是否包含事件类型关键词
2. 检查 `keyword_extractor.py` 中的关键词映射是否包含该事件类型
3. 如需支持新事件类型，按照扩展指南添加

## 13. 性能优化

### 13.1 LLM 调用优化

- **模板优先**：8 种预定义事件类型可直接使用模板，无需 LLM 调用
- **轻量校验**：DAG 校验仅做必要检查，不调用 LLM
- **规则匹配**：IO 配对优先使用规则匹配，减少 LLM 调用

### 13.2 数据库优化

- **连接池**：SQLAlchemy 使用连接池管理数据库连接
- **索引优化**：关键字段已添加索引（event_type, task_type, model_id）
- **只读访问**：模型库表为只读访问，减少锁竞争

### 13.3 缓存策略

- **模型名称缓存**：`ModelRegistryClient` 使用 LRU 缓存模型名称
- **模板缓存**：事件模板在内存中缓存，无需每次查询
