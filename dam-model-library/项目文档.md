# dam-model-library 项目完整文档

## 一、项目概述

**dam-model-library** 是一个用 Python (FastAPI) 构建的**轻量级模型库服务**，为"智能模型工作台"以外的其他系统提供核心的**模型注册**和 **Docker 容器部署管理**能力。

与原 Java Spring Boot 实现的完整系统相比，去掉了 K8s、Kafka、MinIO、Redis、Harbor 等重型依赖，仅保留本地 Docker 容器管理。

**核心功能：**

- 模型注册与信息管理（CRUD）
- 模型与 Docker 容器/镜像的部署绑定
- 容器生命周期管理（启动/停止/重启/重建）
- 模型推理代理（直接推理 + 一次性自动运行）
- 容器日志查看（支持 SSE 流式推送）
- 健康检查与状态同步
- 容器资源监控（CPU/内存）
- IO Schema 管理（输入输出格式定义）

## 四、数据库设计

### 4.1 表关系

```
model_registry (模型注册表)
  ├── 1:1 ── model_deploy_binding (部署绑定表)
  ├── 1:1 ── model_io_schema (IO Schema，可选)
  └── 1:N ── model_operation_log (操作日志)
```

所有关联表通过外键 `model_id` 关联到 `model_registry`，设置 `ON DELETE CASCADE` 级联删除。

### 4.2 模型状态机

```
stopped (默认) → starting → running → stopping → stopped
                  ↘         ↘ error   ↗
```

### 4.3 四张核心表

#### model_registry（模型注册表）

| 字段           | 类型     | 说明                                              |
| -------------- | -------- | ------------------------------------------------- |
| id             | BIGINT   | 主键，自增                                        |
| name           | VARCHAR  | 模型名称                                          |
| description    | TEXT     | 模型描述                                          |
| framework      | VARCHAR  | 推理框架（如 vLLM、TensorRT）                     |
| architecture   | VARCHAR  | 模型架构                                          |
| model_type     | VARCHAR  | 模型类型                                          |
| model_size     | VARCHAR  | 模型大小                                          |
| runtime_status | VARCHAR  | 运行状态：stopped/starting/running/stopping/error |
| owner_id       | VARCHAR  | 归属用户                                          |
| created_at     | DATETIME | 创建时间                                          |
| updated_at     | DATETIME | 更新时间                                          |

#### model_deploy_binding（部署绑定表）

| 字段             | 类型    | 说明                                      |
| ---------------- | ------- | ----------------------------------------- |
| id               | BIGINT  | 主键，自增                                |
| model_id         | BIGINT  | 外键，关联 model_registry                 |
| bind_type        | VARCHAR | 绑定类型：container / image / both        |
| container_id     | VARCHAR | Docker 容器 ID                            |
| container_name   | VARCHAR | 容器名称                                  |
| image_name       | VARCHAR | 镜像名称                                  |
| host_ip          | VARCHAR | 宿主机 IP                                 |
| host_port        | INT     | 宿主机端口                                |
| container_port   | INT     | 容器端口                                  |
| inference_path   | VARCHAR | 推理路径（如 /v1/chat/completions）       |
| health_check_url | VARCHAR | 健康检查地址                              |
| container_config | JSON    | Docker 运行时配置（GPU、shm、网络模式等） |
| extra_mounts     | JSON    | 附加挂载卷                                |
| extra_env        | JSON    | 附加环境变量                              |

#### model_io_schema（IO Schema 表）

| 字段     | 类型   | 说明                      |
| -------- | ------ | ------------------------- |
| id       | BIGINT | 主键，自增                |
| model_id | BIGINT | 外键，关联 model_registry |
| inputs   | JSON   | 输入字段定义数组          |
| outputs  | JSON   | 输出字段定义数组          |

每个输入/输出字段包含：`field`（字段名）、`type`（类型）、`label`（标签）、`targetFormat`（目标格式）、`defaultValue`（默认值）、`required`（是否必填）。

#### model_operation_log（操作日志表）

| 字段       | 类型     | 说明                                                    |
| ---------- | -------- | ------------------------------------------------------- |
| id         | BIGINT   | 主键，自增                                              |
| model_id   | BIGINT   | 外键，关联 model_registry                               |
| operation  | VARCHAR  | 操作类型：start/stop/restart/rebuild/bind/unbind/delete |
| result     | VARCHAR  | 操作结果：success/failed                                |
| error_msg  | TEXT     | 失败原因                                                |
| created_at | DATETIME | 操作时间                                                |

## 六、核心模块详解

### 6.1 应用入口 (`app/main.py`)

- 使用 FastAPI 的 `lifespan` 管理启动/关闭生命周期
- 启动时：自动建表（`Base.metadata.create_all`）+ 启动状态同步定时任务
- 关闭时：停止定时任务
- 配置 CORS 中间件（允许所有来源）
- 注册 8 个路由模块

### 6.2 配置管理 (`app/config.py`)

使用 `pydantic-settings` 从环境变量 / `.env` 文件加载配置：

```python
class Settings(BaseSettings):
    # 数据库配置
    db_host: str = "127.0.0.1"
    db_port: int = 3306
    db_user: str = "root"
    db_password: str = ""
    db_name: str = "dam_system"

    # Docker 配置
    docker_host: str = "unix:///var/run/docker.sock"

    # 服务配置
    host: str = "0.0.0.0"
    port: int = 5001
```

### 6.3 Docker 服务 (`app/services/docker_service.py`)

全局单例 `docker_service`，封装所有 Docker 操作：

- `find_available_port()`：在 8000-9000 范围内自动寻找可用端口
- `create_and_start_container()`：支持完整的容器配置（GPU、共享内存、网络模式、特权模式、设备映射、ulimits 等）
- `_parse_size()`：解析 "16g"、"512m" 等大小字符串

### 6.4 容器生命周期服务 (`app/services/lifecycle_service.py`)

系统核心服务，管理容器的完整生命周期：

- **`start_model()`**：根据 `bind_type` 分支处理
  - `container` 类型：已有容器，直接 `docker start`
  - `image` 类型：仅镜像，执行 `docker run` 创建新容器
  - `both` 类型：优先使用已有容器
- **`stop_model()`**：停止容器但不删除
- **`rebuild_container()`**：删除旧容器后用相同配置重建
- **`get_status()`**：查询实时状态 + 资源使用 + 自动同步数据库与 Docker 实际状态
- **健康检查**：启动后轮询 `health_check_url`，超时 120 秒

### 6.5 推理服务 (`app/services/infer_service.py`)

- **`infer()`**：直接推理，要求容器必须已运行，转发请求到推理地址
- **`run()`**：一次性运行模式，自动启动→探活→推理→自动停止
- 支持基于 IO Schema 的输入校验和输出过滤
- 探活机制：每 5 秒轮询健康检查端点，超时可配置（默认 10 分钟）

### 6.6 状态同步任务 (`app/tasks/status_sync.py`)

使用 APScheduler 每 30 秒执行一次，对比数据库 `runtime_status` 与 Docker 容器实际状态：

| 数据库状态        | Docker 实际状态 | 处理                 |
| ----------------- | --------------- | -------------------- |
| running           | 已停止/不存在   | 修正为 stopped/error |
| stopped           | 正在运行        | 修正为 running       |
| starting/stopping | 超过 2 分钟     | 修正为 error         |

### 6.7 工具函数 (`app/utils/container_utils.py`)

- `generate_container_name()`：生成容器名称，格式 `dam-{name_slug}-{model_id}`
- `is_dam_container()`：判断容器名是否以 `dam-` 开头

## 七、构建与运行

### 7.1 本地运行

```bash
# 1. 安装依赖
pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple

# 2. 配置环境变量（复制 .env.example 为 .env 并修改）
cp .env.example .env

# 3. 初始化数据库（可选，服务启动时会自动建表）
bash scripts/init_db.sh

# 4. 启动服务
uvicorn app.main:app --host 0.0.0.0 --port 5001

# 5. 访问 API 文档
# http://localhost:5001/docs
```

### 7.2 Docker 部署

```bash
# 构建镜像
docker build -t dam-model-library .

# 运行（需挂载 docker.sock 以管理宿主机容器）
docker run -d \
  -p 5001:5001 \
  -v /var/run/docker.sock:/var/run/docker.sock \
  -e DB_HOST=your_mysql_host \
  -e DB_USER=root \
  -e DB_PASSWORD=your_password \
  -e DB_NAME=dam_system \
  --name dam-model-library \
  dam-model-library
```

### 7.3 前置条件

- Python 3.10+
- Docker daemon 运行在同一主机上
- 进程用户有 `/var/run/docker.sock` 访问权限（加入 `docker` 用户组）
- MySQL 实例可用
- GPU 支持需安装 NVIDIA Container Toolkit
